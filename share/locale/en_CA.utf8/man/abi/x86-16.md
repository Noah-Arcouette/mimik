# Name

x86-16 - The x86-16bit Mimik calling convention


# Synopsis

This calling convention is the default used by the Mimik C Compiler for x86
16bit output. This format does not claim compatibility with any other given
format.


# Description

## Type Overview

+--------------+----------+
|    C Type    |   Size   |
+--------------+----------+
| char         |  8  bits |
| short        | 16  bits |
| any *        | 16  bits |
| int          | 16  bits |
| float        | 32  bits |
| long         | 32  bits |
| long long    | 64  bits |
| double       | 64  bits |
| long double  | 64  bits |
+--------------+----------+

## Function Parameters

The first four defined parameters shall be placed in `%ax`, `%bx`, `%cx`, and
`%dx`. Any parameter after the fourth, as-well as all variable argument lists,
shall be pushed onto the stack, with the first argument pushed first.

Example:
```C
extern void function (short ax, short bx, short cx, short dx, short another,
	...);

function(0, 1, 2, 3, 4, 5);
```

Becomes:
```asm
; ...

mov %ax 0
mov %bx 1
mov %cx 2
mov %dx 3
push 4 ; or `mov %ax 4 \ push %ax` if push literal isn't in the architecture
push 5
call function

; ...
```

## Function Stack

The stack clean up is the caller's responsibility. The callee shall not "pop"
any parameters off the stack. All functions shall preserve `%sp` and `%bp`. The
caller shall also not assume the stack values have not been modified. Pushing
a values then calling a function may result in the popped value to differ. The
caller shall also not assume any register other than `%sp` and `%bp` have not
been modified.

## Function Returns

The return value of a function shall be the same as the parameters. Returning
a value will return in `%ax`, if it requires more space it shall fill up to
`%cx`. If more is required, than the caller shall place a pointer in the `%si`
register which the callee shall fill.

## Scalar Types Larger than 16bits

An 8bit value shall occupy a word sized register and stack value, akin to a
16bit value. If a value or type requires more than 16bits in a function return
or parameter it shall expand into the following value, little-endian style.

Example:
```C
extern void function (long ax_bx, short cx, long long dx_stack);

function(0, 1, 2);
```

Becomes:
```asm
; ...

mov %ax 0 ; 0x--00
mov %bx 0 ; 0x00--

mov %cx 0 ; 0x01

mov %dx 2 ; 0x------02
push 0    ; 0x----00--
push 0    ; 0x--00----
push 0    ; 0x00------
call function

; ...
```

Return values shall act in the same fashion but may not expand into the stack.
If more than 64bits are required a pointer in `%si` shall be given by the caller
-- of the appropriate size -- as the return value instead of registers.

## Vector Types

A vector type -- static array or structure -- shall always be passed as a
pointer to the function in the relevant register or stack element. And as a
return value (if not a pointer in the C declaration) shall use `%si` as a
pointer to the return structure to fill.

## Thread-Local Storage

If a program is to need a symbol defined in `_Thread_local` storage is shall
always be relative to the `%es` segment.

## Floating Point Values

Floating points shall be passed as arguments and return values the same as
others without special treatment or loading into the `%stX` family of registers.

Floating points shall be stored in IEEE 754 values, and may make use of the
co-processor instructions, or if not present in hardware shall make use of the
following C library functions:
```C
// Return the sum of the given values
extern      double fadd  (double a, double b);
extern long double faddl (long double a, long double b);
extern      float  faddf (float a, float b);

// Return the difference of the given values
extern      double fsub  (double a, double b);
extern long double fsubl (long double a, long double b);
extern      float  fsubf (float a, float b);

// Return the multiplicand of the given values
extern      double fmul  (double a, double b);
extern long double fmull (long double a, long double b);
extern      float  fmulf (float a, float b);

// Return the dividend of the given values
extern      double fdiv  (double a, double b);
extern long double fdivl (long double a, long double b);
extern      float  fdivf (float a, float b);

// Return the remainder of the given values
extern      double fmod  (double a, double b);
extern long double fmodl (long double a, long double b);
extern      float  fmodf (float a, float b);

// Return the compliment of the given value
extern      double fcom  (double a);
extern long double fcoml (long double a);
extern      float  fcomf (float a);
```

## Register Over View

+-------+-----------------------------------------------+
| `%ax` | First parameter, first return value           |
| `%bx` | Second parameter, second return value         |
| `%cx` | Third parameter, third return value           |
| `%dx` | Fourth parameter, fourth return value         |
| `%si` | Scratch register, or return structure pointer |
| `%di` | Scratch register                              |
| `%bp` | Base pointer                                  |
| `%sp` | Stack pointer                                 |
| `%cs` | Code segment                                  |
| `%ds` | Data segment                                  |
| `%ss` | Stack segment                                 |
| `%es` | Thread-Local storage segment                  |
| `%fs` | First user segment (if present)               |
| `%gs` | Second user segment (if present)              |
+-------+-----------------------------------------------+


# Rationale

The decision of using floating point arithmetic but not st-register family is to
allow non-co-processor and co-processor to intermix without much modification
from either side.
